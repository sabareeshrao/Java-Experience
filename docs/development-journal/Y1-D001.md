# Engineering problem

The operations team still relies heavily on spreadsheet-driven project tracking.

Before we build database tables, CRUD screens, validation rules, or workflow status management, we need the smallest possible Java application that proves:

```text
source code
   ↓
compile
   ↓
bytecode
   ↓
JVM
   ↓
running application
```

The first goal is intentionally small.

We are not starting with Spring Boot, Hibernate, PostGIS, React, Docker, or microservices because that would skip the developer progression we are trying to practice.

# Interview practice from today's work

## 1. What are the advantages and disadvantages of using Java for Enterprise-level development?

**Experience answer:**

Java is useful for enterprise development because the JVM gives us portability, the language has strong typing, the ecosystem has mature libraries and frameworks, and tooling for testing, debugging and production support is strong. The trade-offs are that Java applications can become verbose, JVM applications can have a larger footprint than lightweight alternatives, and the ecosystem changes continuously, so dependencies, JDK versions and frameworks need active maintenance.

## 2. How do you keep up with the continuous evolution of the Java ecosystem?

**Experience answer:**

I connect learning to project changes. I follow JDK release notes and JEPs, framework documentation and dependency release notes, then validate important changes with small proof-of-concepts before using them in project code. Production issues, code reviews and upgrade work also show which changes matter in practice.

## 3. Which editor are you using?

**Experience answer:**

For this Year 1 project I am using IntelliJ IDEA as the primary Java IDE. I also use command-line JDK tools so I understand what the IDE is doing during compilation and execution.

## 4. Which editor do you use for your current project?

**Experience answer:**

The current simulated project uses IntelliJ IDEA because it matches the early Java enterprise development stage. Later projects can introduce IntelliJ when the stack moves deeper into Spring Boot and microservices.

## 5. Do you use IntelliJ IDEA, IntelliJ, or another IDE?

**Experience answer:**

I can work with both IntelliJ IDEA and IntelliJ. For this project stage I use IntelliJ IDEA, while later Spring Boot work will use IntelliJ where appropriate. I do not depend on IDE-specific behavior for basic build and runtime understanding.

## 6. What is the role of the JVM in making Java platform-independent?

**Experience answer:**

The Java source is compiled into bytecode rather than directly into one operating system's native executable. A JVM implementation for the target platform executes that bytecode, which is why the same compiled Java application can run across supported platforms without recompiling the source for each operating system.
