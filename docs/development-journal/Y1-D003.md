# Engineering problem

Day 2 made the runtime visible.

Now the operations team wants the program to support a launch mode from the command line:

```text
java ... GeospatialOperationsApplication survey-import
```

The junior developer notices `String[] args` in the existing `main()` and asks whether we can simplify or change the method signature.

Possible suggestions appear during review:

```java
public void main(String[] args)
```

or:

```java
static void main(String[] args)
```

or:

```java
public static void main(String mode)
```

All three look close to the existing method, but the Java launcher has a specific entry-point contract.

The Day 3 goal is therefore not to memorize the signature. It is to prove which forms compile, which forms launch, and which forms are simply ordinary overloaded methods.

# Why each word exists in `public static void main(String[] args)`

## `public`

The launcher must be able to access the entry point.

A package-private test:

```java
static void main(String[] args)
```

compiled, but launching the class failed because the required public entry point was not found.

## `static`

The launcher calls the method without first constructing our application class.

A test class with:

```java
public void main(String[] args)
```

compiled, but launching it produced:

```text
Main method is not static
```

## `void`

The launcher does not require a Java return value from `main()`.

The method therefore returns no value.

## `main`

This is the conventional method name the Java launcher searches for as the application entry point.

## `String[] args`

This receives command-line arguments.

Today we proved that with:

```text
survey-import
```

which appeared at:

```text
args[0]
```

## Can `main()` be overridden?

Temporary experiment:

```java
class ParentMain {

    public static void main(String[] args) {
    }
}

public class MainOverrideExperiment extends ParentMain {

    @Override
    public static void main(String[] args) {
    }
}
```

Compilation:

```text
FAIL
```

Observed compiler error:

```text
static methods cannot be annotated with @Override
```

So the practical answer is:

```text
main is static
        ↓
static methods are not overridden
        ↓
a subclass may declare another static method
        ↓
that is hiding, not overriding
```

# Interview answers unlocked today

## Can you explain `public static void main(String[] args)`?

`public` makes the launcher entry point accessible. `static` lets the launcher call it without constructing the application class first. `void` means it does not return a value. `main` is the launcher-recognized entry-point name, and `String[] args` receives command-line arguments. In this project I verified `args` by launching the application with `survey-import`.

## Can we overload `main()`?

Yes. I compiled a class containing both `main(String[])` and `main(String)`. Both existed in the bytecode. But the JVM launcher selected `main(String[])`; the overloaded `main(String)` only ran because the standard entry point explicitly called it.

## What happens if `main()` is not static?

The source can compile, but the Java launcher rejects the class as an application entry point. In the experiment it reported that the main method is not static.

## Why is `main()` public and static?

It must be public so the launcher can access it and static so the launcher can invoke it without first creating an instance.

## Can `main()` be overridden?

Not in the normal polymorphic sense because it is static. A static method can be hidden in a subclass, but `@Override` on the experiment failed compilation.

## Can the JVM directly execute an overloaded version?

Not as the application launcher entry point. The launcher looks for the required `public static void main(String[] args)` contract. Another overload is just another method unless our code explicitly calls it.
